# Phase 4：真实渠道校准分析设计

> 代码任务（PR #48）已完成，**真实官方/受控渠道数据采集尚未进行**。最新开发顺序见 [17 号工程收尾路线](17-engineering-closure-roadmap.md)，本文件保留校准算法设计。

## 目标

在 Phase 3 受控实验 `validation.json` 基础上增加离线校准分析，评估：
- Known Positive / Known Negative 的模型身份识别是否有误报、漏检；
- 不同混路由比例下的检出与弃权；
- 同模型不同推理档位的质量差异是否被可靠识别；
- 当前质量退化启发式阈值是否敏感，以及是否存在过度误报。

只使用真实存在的 `report.json`；分析命令 **绝不请求模型 API**、不更改线上阈值，也不制造所谓“官方准确率”。

## 小阶段

1. [ ] Case-level vs run-level 分开统计。重复运行同一个 Case 视为相关样本，不把 5 次重复当成 5 个独立模型供应商。
2. [ ] 分场景 breakdown：0/10/30/50% 混路由、同模型不同 effort、不同 Provider/版本；记录分子分母及弃权。
3. [ ] 质量阈值离线回放：仅对 Contract 匹配、有效 Baseline、完整 `official_baseline_comparison` 的维度试算 k=1/2/3 倍样本标准差；没有数据时无结论。
4. [ ] 独立 Case 的 Wilson 95% 区间作为描述性不确定度；Case 规模不足或来源未独立核实，不得声称统计验证完成。
5. [ ] `validation calibrate` CLI、中文 `calibration.md` / `calibration.json`、测试、CI 与提交。

## 校准指标和边界

- 逐次报告：`TP/TN/FP/FN/ABSTAIN`，仅作调试统计。
- 独立 Case：同一个 Case 必须所有预期运行均有结果、预测一致，才能形成一个“Case 级判断”；分歧/缺失/弃权统一按 Case 弃权，避免挑最好的那轮。
- 灵敏度 `TP/(TP+FN)`、误报率 `FP/(FP+TN)`、覆盖率 `(TP+TN+FP+FN)/(标注数)`。
- 置信区间是单次独立 Case 假设下的描述性 Wilson 区间，并非可外推真实世界的厂商准确率；小样本继续显示“证据不足”。
- 阈值回放绝不自动改默认 `2×stddev`，只给出候选阈值在当前受控实验中的表现。模型和供应商覆盖不足时不能建议直接上线。
- 路由 `routing_fraction` 为**配置目标比例**，不等于实际观察到的分流比例；没有请求级上游日志，不能据此反推出实际流量命中。
- 真实 Kimi K3 / GLM-5.2 官方 Key 和受控网关仍需要实际环境。工具未持有凭据时只完成统计能力与 CI 合成结构测试。

## 完成标准

代码：命令无联网、输出保守完整、指标有分母、有异常/弃权/误报详情，不泄露 API Key，CI 全绿。

数据：Kimi/GLM 至少 3–5 次可信官方 Baseline、同模型自测、换模、不同 effort、0/10/30/50% 混路由真实报告齐备，并检查实际路由日志。这部分必须实际执行，不以 CI 数据替代。
