## 0. 产品目标与非目标

**目标**：单用户、单机 Web+CLI 的 API 模型/供应商准入检测工具：输入 Base URL、Key、声称模型和可选官方/可信 Reference；按模型适用性执行协议、能力和官方专项测试；统一中文报告（结论、证据、适用范围、未知项、费用、历史与导出）。对“是否偷偷换模”“思考档位不符”“混合路由”只给有证据支持的辅助判断，**不能凭能力相似声称权重真伪已认证**。

**非目标**：TTFT/TPS/RPM 性能压测；SaaS/RBAC/租户；任务调度；无监督自动反复重试；自动下载/维护所有第三方 Benchmark；强行给未公开官方规则的模型赋予“官方认证”。

### 完成度口径

不对“模型能力检测准确性”给虚假的百分比。工程用**本计划任务完成项/总项**计量，外部实证单独计量。截至本版冻结，共 **12 项核心开发任务**、**7 项删减/收敛任务**、**5 项最小真实验收**。全部尚未按新验收定义关闭；旧代码可直接复用，不代表必须重写。基线优点是 Web/CLI/协议/基础题/Reference/报告已经具备，主要缺口是官方能力覆盖的证明、执行一致性、真实可比性和简化交互。

## 5. 最小真实验收（5 项；当前未执行）

- **V1 协议官方对照**：至少 Kimi K3、GLM-5.3 官方端点与供应商端点同配置，记录实际请求、响应和参数错误行为。
- **V2 官方专项**：Kimi 官方子集真实跑通且有源码/环境/版本证据；高成本视觉/Agent/长上下文仅在具备条件与预算时单独验收，未测标不覆盖。
- **V3 公开 Benchmark**：真实 lm-eval 固定任务/版本/评分配置；实际样本数与费用可解释，不冒充厂商官方规则。
- **V4 身份受控场景**：官方自比、已知不同模型、低/高思考、受控混路由各至少一组；独立真值足够前不给「准确率」百分比。
- **V5 单机用户闭环**：Web 发起、API 检测、中文报告、历史下载和删除，全流程含密钥脱敏、异常/429/断流、成本展示。

发布条件：P0 代码与 CI 全绿、V1/V2/V3/V5 关键场景具备实际证据、身份能力公开声明服从 V4 的真值覆盖边界；可将未支持高成本专项明示为可选未验证。**完整能力=覆盖当前支持模型和其声明能力的可检查维度，有未支持项透明列出；不等于每个模型所有可能 Benchmark 均已跑过。**

## 6. 维护方法

- 单用户产品，默认只见「开始检测 / 历史 / Reference」，高级选项包含官方专项与 Benchmark，默认不开昂贵外部引擎。
- 每个 PR 带风险说明、运行/缺失环境说明和只与变动相关的必要回归；CI 通过后合并，禁止为凑测试数制造低价值 Mock。
- 每次合并只在本计划标注任务状态与 PR，不追加一套新编号；阶段结果用：`未开始` / `进行中` / `代码已合并` / `真实验收通过`。
- 最终 v0.2.0 不是按 PR 数量发布，而是按报告正确、来源可追溯、官方适用场景清楚、用户能稳定操作发布。

### K1 实际代码交付（首批）

- `model-detect catalog [--model kimi-k3]` 读取统一 `test_catalog`，按 `source_revision/provenance/integration/run_verified/results_attested` 区分**官方固定源码**、**社区标准 Benchmark**、**尚未接入的高级任务**；不调用模型，也不把目录存在视为官方验收。
- Kimi 官方四组协议套件从现有固定源码映射实时生成目录；OCRBench/MMMU/BEAM/DeepSWE 是**候选未集成**，必须先核实官方仓库实际路径、题集和依赖才能开放执行。
- `lm-eval` 使用现有 `data/lm_eval_profiles.yaml` 的题集数据做目录，并标明不是模型供应商的官方套件。
- **强模型天花板效应修复原则**：不再简单增加基础小题的重复轮数。日常试题用于快速筛查；深度层应有困难数学、复杂代码、工具多步规划、严格指令与长上下文的适用 Benchmark。固定数据集的版本、题数、评分器和生成参数，不以单次高分证明真伪，不允许从热门公开题集推出可靠身份检测准确率。
