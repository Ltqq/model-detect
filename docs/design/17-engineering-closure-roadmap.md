# model-detect 唯一执行计划与偏移审查（2026-10-19）

> **当前优先级：M6 工程收尾 → R0 不依赖官方 API 的公开证据路线 → R1 可选真实双端点验收。** 本文件取代旧 G0～F、K1～K12 的未来排期，历史 PR 保留在 GitHub 供追溯，不再复制数套开发清单。版本写为 0.2.0 **不代表已发 Release**。阶段状态必须明确区分「离线代码和 CI 通过」与「真实模型/外部开源引擎验收通过」。

## 不变的用户目标

用户提供声称模型、官方/可信端点与供应商端点，按同一标准运行**官方公开 Pytest 验证器**或**公开 Benchmark 原始评测框架**，保留可追溯的真实结果（测试源码/引擎、数据集/评分器版本、样本 ID、参数、分数和错误），生成长期可复用的官方 Reference，再以相同合同比较供应商，并从一个本地 Web/CLI 查看中文报告、证据和历史。

**工具的职责**：规划调用、引用官方测试/原始评分器、记录合同比较、归纳报告。**不是**自研大模型榜单评分器、百分百鉴定模型权重工具、性能压测平台或企业级 SaaS。黑盒分数一致 ≠ 同权重；能力下降 ≠ 一定偷偷换模。官方公开的测试代码 ≠ 用户运行结果 ≠ 厂商认证成绩。来源未核实则必须 `source_verified=false`；费用未知则不得声称硬上限。

## R0：无官方 API 也必须能交付的最小可用路线（当前优先）

**关键产品决策**：用户无需提供任何官方模型 API Key、账单或官方端点。开发和离线验收不得因为缺少官方 API 而停住。与用户自采 Reference 并列，支持“公开来源参考”：先收录上游仓库固定 commit 的官方发布基准表/公开结果文件，以及原始任务、评分器、版本、模型变体、推理参数、样本数等可核验字段。先完成 Kimi K3 的公开证据样板，再扩展模型；不得因为公开来源只有汇总分数就捏造逐题证据。

- [ ] **R0.1 来源收集**：优先复用 Kimi-Vendor-Verifier 已公开的 K3 评分表与可获取的真实结果资产；记录上游 URL、commit/发布日期、模型名/版本、数据集和指标、评测条件、提供方。每个数值必须有可核验来源；缺字段明确 unknown。
- [ ] **R0.2 等级分离**：区分 `official_published_aggregate`（官方发布汇总）、`community_published_aggregate`（第三方汇总）、`user_measured_reference`（用户实测）、`same_sample_verified_comparison`（逐样本同合同校验）。公开汇总只允许做“背景参照/区间差距”，不能伪装成逐样本同条件 Reference，也不能把差距直接判为换模。
- [ ] **R0.3 供应商单端闭环**：只输入供应商 URL/Key/model，即可执行已有协议/能力/可选公开 Benchmark；无官方账户时照样输出中文报告与 SQLite 历史，并显示公开参考指标的适用性、可比/仅参考/不可比原因。缺多模态等执行器则明确“未覆盖”，不静默替代成简单题。
- [ ] **R0.4 离线真实性检验**：从已发布的真实公开结果构建带来源信息的**非敏感**回归 Fixture，验证来源版本、成绩映射、同条件比较拒绝规则、过期/不可比状态与 UI 报告。不用 mock 结果冒充新的模型实测。
- [ ] **R0.5 发布门槛**：无官方 Key 的单端实际体验、安装/报告/历史、证据等级明确即可发布“可用但非权重认证”的自用版本；需供应商真实调用的验收可由用户将来自行执行，不阻塞完成离线工程与公开证据集成。

**约束**：不写爬虫大平台、不新增重复数据库或评分引擎；直接复用 test_catalog、Reference 只读机制、比较器、已有 Web/SQLite/report。开放许可证与结果发布许可必须核验，分数不等于厂商端点的可重现实验结果。

## R1 的最小实测增强项（有授权端点时才执行）

- [ ] **Kimi-K3**：确认固定源码的官方协议 Pytest 套件在实际环境可执行；官方端点/供应商分别运行并导出按同用例对照的 JUnit 和结果说明；不适用的项标明原因。
- [ ] **GLM-5.3**：官方/供应商同题同参数运行协议与能力任务，核查推理档位在真实请求中传输/实际响应行为；不以 Mock 证明服务端采纳参数。
- [ ] **公开 Benchmark**：固定 lm-eval 版本、实际任务/评分器/数据集修订与样本 ID，官方与供应商在合同一致时可比；MATH-500 的数学依赖、真实评分和难度区分能力要实测。不能复用的旧 Deep v1 Reference 明确标不可比。
- [ ] **Web 单用户闭环**：从输入 Key 到报告/历史/下载/删除，检查 401、429、超时、不完整流式、缺失用例、Key/Prompt 泄露和报告真实性；确保不重复收费。
- [ ] **发布审查**：来源、覆盖、不支持项、token/成本未知、身份判断限制准确；CI 3.11/3.12、构建、单机升级/恢复通过。仅在用户确认后创建正式 Release。

真实验收需要使用用户授权的有效 API 和费用预算。**本地 CI 不连接真实收费模型**。高成本 OCRBench、MMMU、BEAM、DeepSWE 等 Kimi 能力专项，以及代码/Agent/视觉/长上下文完整覆盖尚未开发/实测，不可以与已完成的协议适配混为一谈；不阻塞对**已支持范围**的可用版本，但报告必须直言覆盖边界。

## 每批 PR 结束后的偏移核对（5 项，固定）

1. **是否推进主线**：官方/公开原始测试执行 → 可追溯证据 → Reference 对比 → Web/报告？否则是否属于该主线的真实阻断修复？
2. **是否优先复用**：官方评分器、现有 audit、test_catalog、Reference、报告、SQLite？不另造注册表/评分器/服务。
3. **是否说清证据边界**：原始来源、任务/版本/样本、评分/费用未知、Mock 与真实校准严格分离？
4. **复杂度有无增加**：新增无关 CLI、doctor、自动重试、数据库状态或重复测试是否可以删除？
5. **退出条件是否达成**：对应表格和 PR/CI 可验证；没有完成的明确留到 R 或后续型号扩展，不假称全部完成。

每次判定只可用 **未偏移 / 偏移已修正 / 存在偏移并停止扩展**。如偏移，先删/合并多余抽象，再做下一阶段；已经完成的代码不能反复当做新计划。

### M6 隐私阻断复核：后台异常不得进入 SQLite（2026-10-19，CI 通过 #121）

- **确定性风险**：原 `_run_audit_job`、`_run_reference_job` 使用 `store.fail(job_id, f"{type(exc).__name__}: {exc}")`；第三方 HTTP/子进程异常可能包含密钥、Prompt、响应片段或本地敏感路径，通过 `/api/jobs` 和 Web 历史显示。
- **修正**：保留任务失败状态与超时/文件/配置等固定中文错误类型，彻底避免把未经信任的异常原文入库。模拟第三方异常含假 API Key 与 Prompt，覆盖审计、Reference、SQLite、Web 历史与 API JSON。
- **偏移检查**：未偏移，Python 3.11/3.12 CI 通过并合并 #121。仅属于真实隐私阻断修复，不增加评测器或数据表；外部 Kimi/lm-eval 实测仍属 R。
