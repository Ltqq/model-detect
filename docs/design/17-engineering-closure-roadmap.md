## 0. 产品目标与非目标

**目标**：单用户、单机 Web+CLI 的 API 模型/供应商准入检测工具：输入 Base URL、Key、声称模型和可选官方/可信 Reference；按模型适用性执行协议、能力和官方专项测试；统一中文报告（结论、证据、适用范围、未知项、费用、历史与导出）。对“是否偷偷换模”“思考档位不符”“混合路由”只给有证据支持的辅助判断，**不能凭能力相似声称权重真伪已认证**。

**非目标**：TTFT/TPS/RPM 性能压测；SaaS/RBAC/租户；任务调度；无监督自动反复重试；自动下载/维护所有第三方 Benchmark；强行给未公开官方规则的模型赋予“官方认证”。

### 完成度口径

不对“模型能力检测准确性”给虚假的百分比。工程用**本计划任务完成项/总项**计量，外部实证单独计量。截至本版冻结，共 **12 项核心开发任务**、**7 项删减/收敛任务**、**5 项最小真实验收**。全部尚未按新验收定义关闭；旧代码可直接复用，不代表必须重写。基线优点是 Web/CLI/协议/基础题/Reference/报告已经具备，主要缺口是官方能力覆盖的证明、执行一致性、真实可比性和简化交互。

## 5. 最小真实验收（5 项；当前未执行）

- **V1 协议官方对照**：至少 Kimi K3、GLM-5.3 官方端点与供应商端点同配置，记录实际请求、响应和参数错误行为。
- **V2 官方专项**：Kimi 官方子集真实跑通且有源码/环境/版本证据；高成本视觉/Agent/长上下文仅在具备条件与预算时单独验收，未测标不覆盖。
- **V3 公开 Benchmark**：真实 lm-eval 固定任务/版本/评分配置；实际样本数与费用可解释，不冒充厂商官方规则。
- **V4 身份受控场景**：官方自比、已知不同模型、低/高思考、受控混路由各至少一组；独立真值足够前不给「准确率」百分比。
- **V5 单机用户闭环**：Web 发起、API 检测、中文报告、历史下载和删除，全流程含密钥脱敏、异常/429/断流、成本展示。

发布条件：P0 代码与 CI 全绿、V1/V2/V3/V5 关键场景具备实际证据、身份能力公开声明服从 V4 的真值覆盖边界；可将未支持高成本专项明示为可选未验证。**完整能力=覆盖当前支持模型和其声明能力的可检查维度，有未支持项透明列出；不等于每个模型所有可能 Benchmark 均已跑过。**

## 6. 维护方法

- 单用户产品，默认只见「开始检测 / 历史 / Reference」，高级选项包含官方专项与 Benchmark，默认不开昂贵外部引擎。
- 每个 PR 带风险说明、运行/缺失环境说明和只与变动相关的必要回归；CI 通过后合并，禁止为凑测试数制造低价值 Mock。
- 每次合并只在本计划标注任务状态与 PR，不追加一套新编号；阶段结果用：`未开始` / `进行中` / `代码已合并` / `真实验收通过`。
- 最终 v0.2.0 不是按 PR 数量发布，而是按报告正确、来源可追溯、官方适用场景清楚、用户能稳定操作发布。

### K1 实际代码交付（首批）

- `model-detect catalog [--model kimi-k3]` 读取统一 `test_catalog`，按 `source_revision/provenance/integration/run_verified/results_attested` 区分**官方固定源码**、**社区标准 Benchmark**、**尚未接入的高级任务**；不调用模型，也不把目录存在视为官方验收。
- Kimi 官方四组协议套件从现有固定源码映射实时生成目录；OCRBench/MMMU/BEAM/DeepSWE 是**候选未集成**，必须先核实官方仓库实际路径、题集和依赖才能开放执行。
- `lm-eval` 使用现有 `data/lm_eval_profiles.yaml` 的题集数据做目录，并标明不是模型供应商的官方套件。
- **强模型天花板效应修复原则**：不再简单增加基础小题的重复轮数。日常试题用于快速筛查；深度层应有困难数学、复杂代码、工具多步规划、严格指令与长上下文的适用 Benchmark。固定数据集的版本、题数、评分器和生成参数，不以单次高分证明真伪，不允许从热门公开题集推出可靠身份检测准确率。


## 2026-10-16 K1 第一批交付（待 CI）

- 新增 `evaluation-catalog` 输出来源分类（厂商官方测试 / 社区 Benchmark）、官方 Commit、维度和描述性难度层级。已配置的 `gsm8k`/TruthfulQA 属基础辨识任务，IFEval 属中间层级；这不是经过实证的心理测量学难度认证。

- 对照合同核对 task、引擎修订、数据集修订、评分器修订、实际样本 ID SHA256、生成参数 SHA256。只要缺字段或不同，就不能声称同条件可比。
- 目前仅实现可信目录/合同代码，尚未自动把每轮实际评测的数据集版本与样本 ID 写进 Reference；这是 K5/K8 后续工作，不视为 K1 完结。


## 2026-10-16 K8 可复用离线标准成绩快照（待 CI）

- 新增 evaluation-snapshot-v1 类型，用于保存每次官方/供应商标准 Benchmark 成绩、任务/评分版本、数据集修订、实际 sample ID hash、生成参数 hash、原始证据文件 hash、来源核验状态；旧文件默认拒绝覆盖。

## 2026-10-16 K5 评测产物快照导入增量（待 CI）

- `import-lmeval-snapshot --result-file <results.json> --samples-file <samples.json> --task gsm8k --model glm-5.3 --provider-role official --dataset-revision <rev> --scorer-revision <rev> --output <snapshot.json>`：离线抽取分数、实际有效样本数、明确的 doc_id 集合 hash、原始文件 SHA256 及任务合同 SHA256；只有源产物包含足够字段时才生成不可覆盖快照。

### K5 日志格式兼容补充（2026-10-16）

- 样本证据导入兼容 lm-eval 常用的逐行 JSONL（以及原本 JSON 数组），两者都必须有可复核的 `doc_id`、实际有效题数一致；不导出原始提示词或回复，拒绝重复 ID。不支持的原始日志结构显式失败而非推测补齐。


### K5 真实样本日志采集开关（2026-10-16）

- lm-eval Adapter 的 `build_command/run_endpoint` 增加 `log_samples=False` 参数，用户明确选择时才向官方 lm-eval CLI 传入 `--log_samples`。默认不存储原始逐题问答，保护隐私和减少文件大小；运行成功后才可将原始结果与对应 JSONL 导入 Reference 快照。
- 下一项是把明确用户授权的评测执行与快照导入联通，保证 task、样本日志、实际版本匹配；这次没有调用模型，也没有宣称自动认证官方模型。


### K5 保存运行目录的一键离线导入（2026-10-16）

- `import-lmeval-run --run-dir <run-folder> --task gsm8k --model <model> --provider-role official --dataset-revision <rev> --scorer-revision <rev> --output <snapshot.json>`：自动查找 lm-eval 结果 JSON 与唯一匹配的任务级 samples JSONL/JSON，生成不可覆盖的 Reference 快照；不再要求用户逐个指定文件。
- 多个样本文件、非法任务名、缺少对应样本或完整合同均拒绝，保留未知来源状态。该功能**读取现有真实产物但不运行模型**；仍需真正实装兼容性与未来 Web 主流程对照验收。


### K9 离线多任务统一对照报告（2026-10-16）

- 新增 `compare-evaluation-dirs --official-dir <path> --vendor-dir <path> --output-dir <new-path>`，按 task ID 配对多份存储快照，逐项标明可比/不兼容/缺少配对，生成中文 Markdown 与 JSON；不同数据集或样本 ID 不得计算分差。
- 报告明确未经独立认证的来源快照不能证明模型身份；同类题双高分提示区分度不足。输出目录拒绝覆盖。该 CLI 是 K9 的离线组件，尚未接入 Web 任务历史和真实官方结果自动来源认证。
